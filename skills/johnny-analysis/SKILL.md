# Johnny 分析策略（计算层版）

## 与原版的根本差别

原版把 Fib、EMA、ATR、摆动点、趋势线全部交给模型心算，锚点由模型自选。
这会产生两个无法接受的后果：模型可能凭记忆编造 OHLCV；锚点自由度足以事后凑出
任何目标价（四套 Fib × 任意锚点 × 容差贴合）。

本版把这些全部下沉到 `johnny-ta` Python 包：

| 层 | 谁负责 | 产出 |
|---|---|---|
| 计算层 | `jta analyze` | 行情、指标、候选位、共振证据、确认/失效规则 |
| 叙事层 | 本技能 | 状态解读、交易计划、风险说明 |

**硬约束：叙事层不得自行计算或修改任何价位、比例、指标值。**
JSON 里没有的数字，就是没有；不能推算，不能凭印象补。

## 工作流

### 1. 取数

```bash
jta analyze <SYMBOL> --benchmark <指数> --json
```

半导体用 `SOXX`，美国科技股用 `QQQ`，需要指定时点回溯时加 `--as-of YYYY-MM-DD`。
命令失败或报 `DataUnavailable` 时，直接告诉用户缺什么数据，不要给条件式点位充数。

### 2. 先播报数据口径

任何结论之前，先说明：`data.daily.last_bar`（数据截止）、`adjust`（复权口径）、
`fetched_at`（抓取时间）、`stale` 是否为真。数据陈旧或 stale=true 时必须显著提示。
4H 分析要说明 `bar_alignment`（每交易日 09:30–13:30 / 13:30–16:00 两根）。
`current_price` 默认是前一交易日收盘价，当天点位由它决定，要说成"按 X 日收盘价"；
只有 `price_is_live` 为 true（用户要求 `--live`）时才是盘中价，必须注明未收盘。

### 3. 状态判定

读 `market_state`：

- `phase`：downtrend 下跌 / stabilizing 止跌 / reversal_candidate 反转候选 /
  trend_improving 趋势改善 / range_or_mixed 震荡
- `long_term_vs_vegas`：相对 EMA144/169 隧道的位置
- `daily_ema_stack` 与 `intraday_ema_stack`

`market_state.swing_sequence.daily / intraday` 是最近 6 个已确认摆动点，每个点与前一个同类点比较，
标 HH 更高高点 / HL 更高低点 / LH 更低高点 / LL 更低低点 / EH 等高 / EL 等低（相差不足 0.1 ATR）。
描述趋势时引用它的日期与价格作为依据（对应上游 v2.0.4 第 7.1 节），但它只陈述关系：
单个 HH 不等于上涨趋势确立，上涨支点被破坏也不自动等于下跌趋势建立。
**形态（旗形、三角、头肩、三推等）计算层不识别**，不得声称某形态已形成或已确认；
用户问到时只能说"计算层未识别形态，以下是摆动点事实"。

**4 小时走强但日线未突破关键压力时只算反弹，不算反转。** 低周期不得推翻高周期。
若 `ema_warmup` 里某条 EMA 的 `reliable` 为 false，不得把它当作关键位依据。

再读 `benchmark.regime`（大盘状态，决定能不能开新仓）：

- `state`：up 向上 / range 震荡 / down 向下 / unknown 无法判定；`reason` 是判定依据
- 规则：ADX(14) < 20 → 震荡；收盘 > SMA200 且 SMA50 > SMA200 → 向上；
  收盘 < SMA200 → 向下；其余 → 震荡
- 状态判定必须先说大盘状态，再说个股状态。个股走得再强，基准不在 up 时也不开新仓
- 回测现状：2026-10 修正回测口径后，up 与被拦截状态（震荡 / 向下）的单笔期望没有差异
  （+0.07R 对 +0.08R，z≈0）。开关现在是**未经回测证实的风控规则**，主要防范样本里几乎没出现过的
  下跌市。转述时只说"按规则不开新仓"，不得说成"回测证明能提高收益"，也不要说成"关键位胜率提高了"

### 4. 关键位表

直接使用 `supports` 与 `resistances`，每侧最多 3 行。每行必须写出：

- `label` + `display_text`（动态位带"约"字，不得去掉）
- `role_label`（结构角色）
- `evidence_families`（证据来源）与 `scoring.hits`
- `confirmation` / `invalidation`（确认与失效口径）

`selection.support.mode` 是筛选口径：`proximity` 时 S1、S2 是由近及远、带真实价格反应
（枢轴 / 前日高低 / 缺口 / 价格行为）的达标候选，S3 是更深处证据最密集的一档，作结构覆盖与备用预案——
转述 S3 时要说明"价格要先失守 S1、S2 才相关"，不要暗示它是当前重点；`legacy` 时三档按命中数挑选，
可能离现价很远，要提醒近处结构未入选。

`structure`（需显式 `--selection structure`，默认仍是 proximity）：S1、S2 选法同 proximity；
`role_label` 为"日线结构支点"的那一档，是日线最近一个已确认的摆动低点 / 高点（上游 7.1 节
"维持趋势的结构低点"）。`selection.*.structure_pivot` 给出它的日期、价格和 HH / HL / LH / LL 关系，
转述时说明"跌破它意味着日线这一级的上涨结构受损"，它同样是备用预案，不是当前重点。
`placed` 为 false 时原样转述 `note`（已入选 / 证据不足 / 离已入选点太近）。被它挤掉的原第三档在
`crowded_out` 里，按上一条纪律不得提升为正式关键位。

不得增删关键位，不得把 `selection.crowded_out` 里的未入选点提升为正式关键位。
`selection.*.gap_note` 非空时，必须原样告知用户某侧证据不足，不能用弱点补数量。

**整数关口**：`ladder` 是按价格从高到低排好的完整阶梯（关键位 + 整数关口 + 现价），
`round_levels` 里每个整数位带 `tier`（整数 / 半整数 / 大整数）和 `between`（落在哪两档之间）。
描述路径时可以把它们穿插着说，例如"R2 之上先看 1800 整数关口，再到 R3"。
关键位行里有 `round_number` 时，说明它的展示区间本身含一个整数位，顺带提一句即可。
整数关口只是心理参考：不得当成 S/R 编号、不得拿来做入场或止损、不要说它"支撑很强"，
`round_levels_note` 里写明了回放检验没有发现它比旁边的非整数价位更守得住。

**关于 `scoring.hits`**：这是证据类型的计数，不是加权评分。八项彼此高度相关，
求和没有统计含义。转述时必须带上这个限定，不得说成"评分 5 分所以很强"。

### 5. 当前位置与是否交易

读 `position_zone`：

- `at_support`：评估低吸，但必须等 `confirmation` 条件成立，禁止连续下跌途中盲接
- `at_resistance`：评估止盈减仓或等突破，不在压力下方重仓追涨
- `between`：**默认不交易**，明确写出"不交易区"，不要勉强给方向

### 6. 左右两侧建议与入场方案

**每个标的都必须先给左侧、右侧两项建议**（上游 v2.0.5），直接读 `sides`：

| 侧 | 取自 | 写什么 |
|---|---|---|
| 左侧 | `sides.left`（L 左侧支撑直入） | `status_label` + `reason`；入场、S（`support_basis`）、止损 `0.99×S`、盘中触发口径、T1、收益风险比 |
| 右侧 | `sides.right`（C 右侧突破回踩） | `status_label` + `reason`；尚缺什么确认、入场、止损、T1 |

- 任一侧不适用也要写出状态与原因，**不得省略**。左右侧是入场时机的区分，不是多空。
- 状态五种：等待到位 / 等待触发 / 到位可执行 / 不合格 / 数据不足。"等待"不是"不合格"，
  "到位可执行"也不代表已经成交。
- L 的止损是支撑原值下方 1%，**盘中价格达到或低于即离场**，不等收盘、不加缓冲；
  1% 是支撑下方的距离，不是从买价亏 1%，也不是账户风险 1%；跳空时实际亏损可能超过计划。
  这个 1% 是上游作者的用户指定的配置，不是 Johnny 公开参数，转述时说清楚。
- `validated` 为 false 的方案（目前是 L：期望为正，但没跑赢距离匹配的随机对照）必须标注
  "未经回测验证，仅作参考"。它照常进看板"可执行"分组，标注不能省。
- 两侧作为备选或分批时共享同一份总风险预算，不能各用一份完整预算。

然后**直接转述 `plans` 数组，不要自己编。** 每套已经算好入场、止损、止损依据、
T1/T2、收益风险比、计划仓比例、状态和取消条件。现在只有三套：L 第一支撑直入、
B 更深支撑 + 等止跌确认、C 右侧突破回踩。原来的 A（第一支撑 + 等确认）已于 2026-10-07 删除——
它与 L 同档同入场价，回测里 87% 的成交与 L 重叠；JSON 里不会再出现 `aggressive`，不要凭记忆补出 A。

- `executable` 为 false 时，必须把 `blocked_by` 的每一条原样说出来。
  最常见的是收益风险比低于门槛（低吸 2.0 / 右侧 1.5）——那就是"不交易"，
  不要改写成"可以小仓试试"。
- `entry_level` 说明这套计划实际用的是哪一档。它**不一定是 S1/R1**：
  距现价过近的档位可以按 `MIN_ENTRY_DISTANCE_ATR` 排除在入场之外（默认 0，即不排除）。
  `entry_note` 非空时要转述被跳过了什么。
- `blocked_by` 里出现「大盘状态」时，L/B/C 全部因基准不在向上状态而阻断。
  原样说出基准、状态和理由，不得建议"小仓先试"或"等个股自己走强就能做"。
- `cautions` 非空时原样转述：大盘状态无法判定（没有基准）要提醒用户人工确认大盘；
  若含仓位缩减，计划仓已按 `position_scale` 缩减。这些是降级不是阻断，要说清楚区别。
- `sizing.warning` 非空表示名义金额超过账户净值，必须提醒需要保证金或缩减股数。
- `tranche_text` 说的是**计划总仓位**的比例，不是账户资产的比例。
- 传了 `--account` 时每套带 `sizing`，直接引用股数与名义金额。

持仓者方案读 `holder_playbook`：分批止盈档位、保护位抬升规则、破位处理。

### 7. 事件风险

读 `events`：

- `event_mode` 为 true 时，先说事件与距离（`event_mode_reason`），
  再说所有计划都已被事件阻断。不要给"事件前抢跑"的入场建议。
- `historical_earnings_moves` 是这只票历史财报后次日的跳空幅度（含 ATR 倍数）。
  用它说明事件风险有多大，比笼统说"注意财报"有用。
- `news` 是**未核验的外部标题**，只能列出并标注来源时间，不得据此推断方向，
  也不得让它影响任何点位。
- `available` 为 false（例如 `--as-of` 回放）时，如实说明事件信息不可用。

### 8. 仓位

用 `position_sizing.formula`：`数量 = (账户净值 × 单笔风险比例) ÷ |入场价 - 止损价|`。
波段单笔风险约 0.5%–1%，杠杆 ETF 约 0.25%–0.5%，但用户自己的上限优先。
先定失效位再算仓位，不得为放大仓位而放宽止损。

### 9. 需要图时

用户要"技术地图""图表""可交互的图"时，跑：

```bash
jta chart <SYMBOL> -b <指数> --account <净值> --out <path>.html
```

生成自包含 HTML（日线结构图 + 4H 执行图 + 关键位表 + 交易计划，图层可切换）。
**不要自己画图、不要手写 SVG、不要凭记忆生成 K 线**——
模型手上没有真实 OHLCV 时画出来的是示意图，而它看起来会非常可信。

### 10. 收尾必须交代

- `known_gaps` 全部列出（TD Countdown 13 未实现、基本面否决层需人工、历史回放时事件与市值模块不可用等）
- `validation_disclaimer` 原样带上：前向验证显示这些关键位的守住率与同距离随机价位
  没有可检测差异。不要把 `hits` 说成胜率或强度评分。
- 基本面提醒：技术支撑不覆盖重大基本面恶化。周期股的低远期 PE 可能来自周期高点利润，
  需人工检查盈利预测、毛利率、资本开支与客户需求。

## 不可违反的纪律

- 先活下来再谈收益；风险说不清就不下单。
- B/C 不猜底，等确认；L 是事先定好的左侧试错，到位可直接尝试，但止损必须在入场前定死。
- 触及任何一条线都不构成买卖；确认与失效口径必须在入场前定死，事后不得更改。
- 不在支撑与压力中间强行交易。
- 止损后不补亏损、不死扛；重新出现信号才能重新交易。
- 动态位（EMA / Vegas / 趋势线）必须保留"约/参考位"标注和数据时间，
  不得写成永久水平价。
- 不复用历史静态点位，每次重新运行 `jta analyze`。
- 不把指数、原油与个股的阶段性相关写成永久因果。
- **不自行计算任何数字。** 这是本版存在的理由。

## 已知局限

- 数据源为 yfinance，仅覆盖美股；4H 由 60m 聚合，Yahoo 侧 60m 历史上限约 730 天。
  60m 不折分红，4H 已按日线逐日缩放到同一复权口径（`data.intraday_scale`）。
- 共振命中数经前向验证（7 标的 / 973 条已判定观察）未发现超额价值；
  八项里只有"指数同向"显著，而那本质是顺势过滤，与 Fib 无关。
- 自定义 Swing Structure（BUY/ADD/TP 阶梯线）无公式，未实现，也不做代理伪装。
